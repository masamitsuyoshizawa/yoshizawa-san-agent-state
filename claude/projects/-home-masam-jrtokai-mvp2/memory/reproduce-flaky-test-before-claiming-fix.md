coord の木で部品の試しが時々 105/106 に落ちた。dgr は再現しないまま「図の読み込みを待たずに測ったから」と推して待ちを足し、5 回通ったので直ったと知らせた。coord の木では直しの後も落ちた。図の応答を 0.6 秒遅らせて再現すると、足した待ちは効いておらず(読む前の図は幅 0 で待つ物から外れた)、本当の訳は画面そのもの(選ぶ表の送りの高さを図を読む前に決め、決め直さない)だった。

**Why:** 揺れは環境(負荷・遅れ)で出たり出なかったりするので、自分の木で通った回数は、直った証にならない。推しで直すと、画面の欠け(利用者にも起きる)を、試しの待ちで隠すところだった。
**How to apply:**
- 揺れを知らされたら、まず落ちた時の値を出す形にし(どの数が違ったか)、落ちる形を作って再現する(負荷だけで出ない時は、遅れ・順を入れる)。
- 訳を「測り方だけ」か「画面(作り)そのもの」かに分けて確かめる。測る前の待ちを足すのは、作りに欠けが無いと確かめてから。
- 報告では、再現できていない推しは「推定」と書き、通った回数を直った証として書かない。
