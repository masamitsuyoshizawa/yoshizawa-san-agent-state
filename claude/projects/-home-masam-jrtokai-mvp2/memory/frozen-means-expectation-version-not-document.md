「凍結済みの本の数は書いてよい」と dec に書かない。受入の独立(CLAUDE.md §4)は、期待の**版**と、その版が照らす**欄**の単位で当てる。本が前の版で凍結済みでも、acc が新しい版(階層の期待の第 2 版など)を作っている間は、その版が照らす読取の値(数・種類ごとの内訳も)を、連絡文と docs に書かない。書いてよいのは、合否・当たり 0・置き場・指紋・道具の版・試しの数。

**Why:** 決168 §5 の 3 に、coord が「凍結済みの 4 本の数は書いてよい」と書いた。dcr がそれに拠って、階層の試し(段 2)の 4 本の読みの数を rep 0209・0228 と info 0227 に書き、coord も決194 に 1 つ写し、main に入れた。acc の階層の期待の第 2 版は凍結の前だった。kgb が数を git 外に置いたのを見て、dcr が気づき、知らせた。acc は main を取り込んでいなかったので、独立は損なわれなかった(決195 で訂正・値は外した)。coord は利用者への報告にも、まとめの数を書いていた(利用者は期待の記入票に答える人でもある)。

**再発(2026-11-24・図面・決212 §3):** acc が物差しの第 20 版で、2a8c の新しい欄(同じ番号の記号の束ねと部分・接点の先の配線がつながる機器)を照らす、と 2026-11-23 に知らせた後も、dgr の rep(cc acc)と coord の既読の注記と利用者への報告に、その欄の数(行を採った機器の数・部分ごとの記号の数・名称表の問いの状態ごとの数・番号の組の数)を書き続けた。開発状況の Artifact を作る時に気付いた。acc は道具で照らして「読んでいない」と答え(rep 20261124-1117)、前の rep の値は外さなかった。今は、dgr は有無と置き場と sha16 だけを書き、数は git の外(coord は、そのファイルを直接読んで確かめる)。acc 宛ての dec と info に、これらの数を書かない。**受入の側が「新しい欄を照らす」と言った時点で、その欄の数を連絡文から外す。**

**How to apply:** dec や計画に「数を書いてよい」の例外を書く前に、acc が、その値を照らす新しい期待を作っていないかを確かめる。段ごとの rep を取り込む時、凍結の前の値が入っていないかを、既読の前に見る(見つけたら、main に入れる前に止める)。利用者への報告にも、凍結の前の読みの数は、形(通った・変わった所の有無)だけにする。迷う時は、git 外に置かせ、置き場と指紋だけを書かせる。関連: [[acceptance-independence-no-element-kinds]]・[[check-counts-by-type-leak-acceptance]]・[[acc-a-layer-values-before-freeze]]。
