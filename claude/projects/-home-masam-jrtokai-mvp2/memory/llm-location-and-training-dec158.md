決158(利用者・coord の画面・2026-11-19): 顧客の資料と、そこから作った物の置き場は国内に限る。開発の間は、保存を行わなければ、処理の場所が国外になる LLM も使ってよい。LLM は、学習に使われない設定で使う。CLAUDE.md §7 に足した。車両は当面 MCP サーバーの対象外・図面の作業は顧客の計画の案の確定まで今のまま続ける、も同じ dec。

- 経路: API(Bedrock・口は東京・モデルは `global.` の推論プロファイル = 処理は国内に限らない。`scripts/dcr/llm_vision.py` と `scripts/drawing/vision_call.py`)・`claude -p`・`codex exec`・`agy -p`。
- 確かめは済み(2026-11-19): 利用者が、4 つの経路とも学習に使われない設定だと答えた。記録は `docs/09_LLMの経路と設定の確かめ_20261119.md`・知らせは info 20261119-1326。待ちは解けた。経路を足す時・設定を変えた時は、確かめ直して記録に足す。coord は設定の画面を見ていない(利用者の答えによる)。
- 決162(2026-11-19): 「保存」は、国外の置き場に置かない意味。LLM の相手の側の一時の保持は当たらない。確かめで見る点は「学習に使われない設定」の 1 つ。名称表の見直しは図面の 2 冊を先にし、文書の側は結果の後に諮る。

**Why:** 顧客の来期の計画の案に、国内の保管と、学習に使われない保証の要件がある。開発の間の試作にも当てると利用者が決めた。

**How to apply:** 「国内のリージョン」と書く前に、モデルの呼び方(`jp.`・`apac.`・`global.`)まで見る。口のリージョンだけでは、処理の場所は分からない。関連: [[canonical-llm-hold-until-company-names-masked]]・[[spec-draft-261111-feasibility-table]]
