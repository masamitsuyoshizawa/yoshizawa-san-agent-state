文書系(図面系も同じ)の期待を acc が凍結するまでは、連絡文と docs に、守りや検査の結果を「合否」と「当たり 0」だけで書く。次のことは書かない。
- 読取の出力に、どの種類の要素があるか・ないか(例:「表やセル由来の要素は無い」)。
- なぜ 0 なのかの説明。
- 「〜にまたがる要素 1 つ」のような、要素の数と範囲。

**Why:** 2026-10-30、dcr が info 2344 §4 の「今回の当たり」の括弧に、0 の理由として要素の種類の有無を書いた。kgb が、これは受入が照らしうる件数の形(0 か 0 でないか)に当たると指摘した。main に入っていたので本文は直さず、次からの注意になった。総数を伏せても、種類ごとの有無や内訳は、受入の照合の下限や形を示しうる(決22 §4 と同じ型)。

**How to apply:** 知らせや記録を書く前に、件数・有無・内訳・理由の括弧が、読取の出力の形を明かしていないかを読み直す。漏れの検査の道具(leak_check.py)は顧客の語を見るもので、この種の値は拾わない。利用者への会話の報告は、この制約の外(git に入らない)。関連: [[remerge-main-before-writing-comms]]
