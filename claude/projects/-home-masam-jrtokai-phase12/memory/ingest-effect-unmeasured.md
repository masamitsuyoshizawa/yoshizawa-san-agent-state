**`ingest_pipeline` の担保(加法・冪等・ダイジェスト・rehearse)は「正しく入ったこと」の担保であって、「入れる価値があったこと」の担保ではない。** X15 は**既定の変更**にホールドアウト実測を求めるが、**データの投入そのもの**には効果測定の要件が無かった。この穴を埋めるのが監査項目 **X17**(`audit_dkb.py --x17`)。検査は 3 段で、(a) 診断コードから参照されているか (b) 評価で実際に発火するか (c) 効果の実測記録があるか。

**実例**: 2026-08-28 の案F で `SUPPORTED_BY_FIELD` 475 本を投入したが、検討書は案F を「様式採用後の**発展枠**」と位置づけ検証計画に入れていなかった。**約 1 年間、LOO700 513 問・条件①④とも加点 0 で、1 度も発火していなかった。**

真因は**引き当ての暴発**。`target` の相互部分一致で「ジャーナル」1 語が 32 概念を返し、下流の概念照合がそれを正しく全部落としている。**当初「概念の粒度が違う」と説明したが誤りで、実例まで降りて判明した。**粒度説のまま進むと寄せ先を類型へ寄せる対策になり、暴発した概念が当たって誤加点が増える方向だった。根治は `target` の設備接地。

**型の名前**: 「効果を測らずに投入する」。既存の [[estimates-not-labeled-as-measurements]]「推定を実測と混ぜない」、「成果物は残るが条件が残らない」に並べる。

あわせて **X5(g-0) 静的資源の棚卸し**を新設。定義は「**評価対象の事故から作られ、診断で読まれる資源**」。従来 X5(g) が 3 層辞書を**個別列挙**していたため、同じ性質の `FieldCheck` / `b_isolation` 質問が洗い出されず 1 年近く検出されなかった。**個別列挙が漏れの原因**。

**Why:** 投入が正しく行われたことと、その投入に意味があったことは別の担保である。前者だけ整備すると、誰も通らない経路が積み上がる。
**How to apply:** 新しい投入を行ったら X17 に行を足し、効果の実測を添える。診断への接続が承認外のものは「接続が承認されたら測る」条件つきで並べる。関連: [[ingest-pipeline-enforcement]] [[dkb-audit-state]] [[verify-in-separate-process]]
