決216(観測文の接頭辞・2026-10-09): coord が fed の推し(x003)を dkb に伝えた → dkb が自案 (a) を見送り → 同時に fed が (a) に乗り換え → coord は「両者 (a) で一致」と諮った(その時点で fed は既に撤回して x003 に戻していた)→ 利用者は (a) を選択 → dkb が改訂 2 と LOCKS 予約まで進んだ後に訂正して再度諮り、x003 に。

**Why:** peer の推しは coord の伝言そのもので動く。伝言を往復させると推しが入れ替わり、諮る文が書いた時点で古くなる。利用者は coord の前提を信じて選ぶので、前提の誤りは決定の誤りになる。

**How to apply:**
- 推しを利用者に書く直前に `git fetch` + main の該当便の `status`/注記を読み、「誰が今どの案か」を時刻つきで確かめる。
- peer A の推しを peer B に伝えるときは「A の推し(時刻)」と書き、B に「自案を取り下げよ」と読める言い方をしない。
- 推しが 1 往復で入れ替わったら、両者を同じ場に(dec の前に短い info で)揃えてから諮る。
- 前提を誤って諮ったと分かったら、その場で訂正して再度諮る(決定を既成事実にしない)。手戻りは coord の責任として dec に書く。
