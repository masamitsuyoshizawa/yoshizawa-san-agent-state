利用者の方針(2026-11-24 21:2x・決364 追補 110・原文は dec に在る): 推論 KB(決364)で、言い回しの形の判断は「人が判断しても迷う・複数の人が見れば別の判断が一定の割合で混ざる」所。**求めるのは 100% の切り分けでは無く「そうである確率が高そう」で十分。白黒で切り捨てず、グレーゾーンも設けてデータを作り、予想する時もグレーを使う。「全く予想できない」を「確率は低くても、ある程度、予想できる」にするのが目的。LLM による曖昧さも、ある程度、許す。曖昧さを積極的に取り入れるアプローチを、いろいろなモデルを使い、知恵を絞る。**

**進み(2026-11-24 夜・決364 追補 111〜123)**: pla・rkb・agy の 3 つの案がそろい、coord が計画 改訂 2 を書いて、利用者が Plan Mode で承認(docs/計画_決364_推論KB_coord_20261122.md の §12・直しは §12-11 が先)。芯 = 行の読みを読み手ごとの票で持つ(LLM A = jp の Claude Opus 4.7・LLM B = sat-sandbox の Bedrock の別の会社のモデル・型 v0/v2 は弱い見張り・人の答え)/ 予想の計算は決定論のまま / 排除は消さずに下げる / 後知恵は 3 水準(S0・S1・S2)の成績を並べ、「当時の入力で拾えた」と言うのは S0 ∩ 時点を証せる ∩ 類例なし、だけ / LLM の上限 400(見積り 363)/ 順 = 計算の仕様の固定 → T0(下見・LLM 0)→ 承認の紙 2 → T1。P0 で、GPT 系(global の口 = 国外を含む処理)と Mistral Large 3(東京)が、作り物の入力で呼べる事を確かめた(Vertex は AWS の外なので使わない)。開発用の代表 13 のうち今の方式の外れは 7(主の物差しの分母)。最終の群の数は dkb だけが持ち、dec と rkb への便に書かない。**実の記録での LLM の呼び出しは、承認の紙 2 の後**(紙 2 は rkb の案 3 待ち・rev の確認を経て諮る)。

**監督についての学び(同じ夜)**: 計画の最初の字に「読みの部分は『危ない例が 1 つでも在れば不可』では判じない」と書き、それを rev への依頼にも入れたところ、Claude Code の自動の権限の判じに「監督を弱める恐れ」として止められた。**方針(作る物の合格の決め方を緩める)と、確認役に基準を緩めさせる事は、別**。rev の物差しは変えず、rev は見つけた例を全部重さつきで報告し、進むか止めるかは数を見て coord と利用者が判じる、に直して承認を得た(追補 115)。止められた命令を言い換えて通さず、記録だけを分けて書き、利用者に申告した。

**Why:** 同じ日に、言い回しの型で「切る所」「済んだか」「どの設備が正常か」を読む道具が rev を 3 度通らず(句点と読点・括弧・語の順で逆の結果に成る)、coord が型で切る方式を止めて「人が画面で決める / 切らない / 終える」を諮ろうとした。利用者の境の例 12 問でも、設計者の案と違う選びが 6/12 だった。利用者は、白黒の正しさを積み上げる向きそのものを、違うと判じた。

**How to apply:** 推論 KB では、「危ない側の例が 1 つでも在れば不可」の物差しで、道具を止めない。確からしさつきで持ち、迷う行を捨てず、「排除」は消すので無く重みを下げる。評価は「全体として、どれだけ当たり、確からしさが、どれだけ当てに成るか」で測る。ただし、これは向きの決めで、計画 改訂 2(LLM に任せる範囲の新しい線 = 不変原則 1 の例外の引き直し・回数・評価の物差し)の承認までは、LLM を呼ばず、設定と道具を変えない。案は pla(独立の計画)・agy(調べ)・rkb(設計)の 3 系統に頼み、coord がまとめて rev の批評の後に諮る。記録の事実(B・D-KG)と混ぜない・伏せた本文だけを LLM へ・評価の群の隔離、は変わらない。関連 [[why-reasoning-kb-r364]]・[[rkb-stage1-design-state]]。
