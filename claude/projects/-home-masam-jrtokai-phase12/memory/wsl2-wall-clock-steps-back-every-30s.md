この PC(WSL2・2026-11-19 に測った)では、壁の時計(`time.time()`・CLOCK_REALTIME)が **30 秒ごとに約 1.35 秒戻される**(0.25 秒の内に約 −0.60 秒と −0.75 秒の 2 度)。単調の時計(`time.monotonic()`・`perf_counter()`)は戻らず、5 分の測りで止まりも無かった。5 分(単調 300.008 秒)で壁の時計は 285.458 秒しか進まない(仮想機械の中の時計がホストより約 4.8% 速く進み、ホストの時刻へ合わせ直されている見込み・推定)。WSL2 の各ディストリと Docker Desktop の容器は同じ核を使うので、容器の中も同じ(推定)。

**Why:** 決351 の手元の演習(dkb の p12)で、「口の秒 3600 ms なのに木の予算切れ(単調で 5 秒超え)」と「普通 1.8 秒の木が 0.37 秒」が出て、食い違いに見えた。壁の時計で測った秒が、戻りを跨いで約 1.35 秒短く出ていただけだった。

**How to apply:** 手元の秒(kg_api の `meta.latency_ms`・`elapsed_ms`・v3 の写しの `s`・待つ道具の秒)を読む時は、30 秒ごとの戻りを跨いだ呼び出しは約 1.35 秒短く出ると読む。止まりや速さを判じる時は、時計に依らない数(診断の回数・予算切れの数)か、呼ぶ側の `time.monotonic()` で測る。EC2(chrony)ではこの形の戻りは起きない見込み。測りの道具 = 0.05 秒ごとに 3 つの時計を読み、食い違いを記録する短い Python(5 分で足りる)。関連: [[r351-remask-and-r355-stage-a-bkb]]
