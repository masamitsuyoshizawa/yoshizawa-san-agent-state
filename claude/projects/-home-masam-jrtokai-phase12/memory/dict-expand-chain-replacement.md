**D-KB の `_dict_expand` は、別名ペアを順に `q2 = q2.replace(s, c)` し、挿入した正準名の中を再走査していた。** その結果「バックアップ受信器故障」が「踏切用自動列車停止装置受信器受信器故障」のような壊れた文字列になり、症状照合が失敗していた。LOO700 567 問のうち **41 問**で発生。

2026-09-15(dec 20260915-0400)に是正。`DKB_DICT_EXPAND` の既定を **v2** に。規則は 4 つ。

1. 非重複の単一パス最長一致(挿入した正準名の中を再走査しない)
2. **正準名を恒等エントリとして最長一致表に入れる**(これが無いと既に正準で書かれた箇所の一部が別名として再マッチする)
3. 同一正準の隣接重複を抑止
4. 曖昧な表層形は文脈(同エントリの他の別名・正準名)で決め、絞れなければ**展開しない**(旧実装は file order で決めていた)

効果: 反復 **41 問 → 1 問**、処理時間 0.09 → 1.24 ms(先頭文字で索引)、**判定値は不変(c+p 294)**。

**あわせて「弱条件別名の一律除外」(dec 20260915-0130 A)を撤回した。** `DKB_ALIAS_FILTER` の既定は `""` に戻り、弱条件 177 件は辞書に残る。一律除外は「弱条件が誤同定を生む」という説明で入れたが、実際は上記の連鎖置換を**偶然迂回**していただけだった。辞書検査 `dict_lint.py` の検査 A(重複語)277 件の内訳が `confirmed` 33 / `proposed` 244 / **弱条件はわずか 4** で、弱条件を外しても確定済み別名で同じことが起きると示されたのが決め手。

辞書側の機械検査(X1-3: 検査 A 277 / B 曖昧 123 / C 内包 370)は **2026-09-23 に閉じた(dec 20260923-0030)。辞書の変更は 0 件**で、「検査に掛かるが是正しない」と監査台帳に記録済み。根拠は 2 回の同一バッチ測定: 段 1c(別名削除 3 アーム)と段 2 の S 規則(同定の非重複最長一致)。どちらも判別できず悪化側。**機序**: 設備同定は最大 2 設備の枠で、関係の薄い設備を外しても空いた枠に別の設備が入り候補が入れ替わるだけ(「候補が減るから悪化」の推定は外れた)。**再開条件**: 辞書や同定規則を変えたくなったら、まず `DKB_DICT_CFG`(辞書の写し)か `DKB_EQ_NONOVERLAP` のような既定 OFF のフラグで「直すと良くなるか」を測る。

**誤りの型(繰り返さない)**: 候補レベル(第 1 位・候補列)の改善を判定レベル(verdict)の改善と読み替えた。悪化 1 件にもっともらしい説明を付けた時点で候補列の検算を止めた。

**Why:** 表面の説明が付いた時点で止めると、その下の真因が見えないまま誤った是正が正式化される。
**How to apply:** 候補レベルと判定レベルは別の量として必ず分けて報告する。原因の説明は生成物(候補列)を実際に見るまで確定しない。関連: [[loo700-baseline-judge-v2]] [[verify-in-separate-process]] [[estimates-not-labeled-as-measurements]] [[dkb-audit-state]]
