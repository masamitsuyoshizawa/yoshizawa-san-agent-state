2026-09-24、W2 で `ingest_pipeline.py` を LOCKS に予約して変え、演習が合格したので解放した。その 1 時間後、R2 以降の経路のために同じファイルへ +7 −3 の追いの変更(G14 が第 2 相の計画を状態に残す)を入れたが、**予約を取り直さなかった**。コミットの直前に気づき、LOCKS に「予約せずに変更した」と事後の記録を残し、rep にも書いた。

**Why:** 大きな変更の予約が頭に残っていて、「同じ作業の続き」だと感じた。解放した時点で予約は無く、他のセッションはその間に同じファイルを触ってよい状態だった。変更が小さいことは、予約を省く理由にならない。

**How to apply:** 共有スクリプト(OWNERS / LOCKS の対象)を開く前に、LOCKS に自分の「保持」の行が今あるかを見る。無ければ、行数に関わらず予約と info を先に出す。予約を解放するときは、同じファイルに追いの変更が要りそうかを考え、要るなら解放を遅らせる。関連: [[session-comms-protocol]]

**再発(2026-09-28・coord)**: 決125 の EC2 kg_api 置換を、dec に手順表を書いたことで予約した気になり LOCKS を取らずに行った。事後記録で補った。**dec の手順表は LOCKS の代わりではない。EC2 を触る直前の 1 手は必ず LOCKS 行の追加。**

**3 回目(2026-09-29 00:45・fed)**: 決139 の表示の札の文言(fed 所有の Dify プラグイン・指令 UI・demo_v10)を、coord の「触る前に LOCKS と info」が届く前にローカルで編集した。自分の所有でもプラグインは EC2 に載る共有の表示なので、編集を始める 1 手目で LOCKS の行を書く。事後に気づいたら「編集の後に記録した」と行に書く。
