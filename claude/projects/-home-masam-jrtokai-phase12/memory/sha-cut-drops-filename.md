複数のファイルの sha16 を `sha256sum a b c | cut -c1-16` で採ると、出力からファイル名が消え、並びの順で当てはめることになる。2026-10-02 の F1・F4 の rep(20261002-0439)で、`docs/計画…md` と `kg_api/sources/dkg_tree.py` の sha16 を入れ替えて書き、ARTIFACTS の行とコミット 488329a0 の説明文にも同じ誤りを写した。coord が現物で再計算して見つけた(rep 0442)。道具が自分で計算して残した記録(render_check.json の dkg_tree_sha16)は正しかった。

**Why:** 版の値は照合の要。入れ替わると、読む側は別の版を照らしてしまう。数字の形が正しいので自分では気づけない。
**How to apply:** sha16 は必ずファイル名と同じ行に出す(`printf '%s  %s\n' "$(sha256sum f | cut -c1-16)" f` の形か `sha256sum f | cut -c1-16` を 1 ファイルずつ)。rep に写す値は、できれば道具や Python で名前と対にして生成し、手で並べ替えない。関連 [[verify-filenames-before-citing]] [[criterion-not-tool-output]]
