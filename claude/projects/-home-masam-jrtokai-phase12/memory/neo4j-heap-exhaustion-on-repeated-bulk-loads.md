手元の一時の B(rehearse_env.py が起こす・ヒープ 1G・ページキャッシュ 256M)に、全部消して B の driver 書き出しを読み込む操作を重ねる。2 度までは 7 回とも通り、3 度目は 5 回とも外れた。外れの字は「Java heap space」で、取引が巻き戻される。外れる時は約 1234 秒かかり、途中の状態(辺 0・一時の索引 _exp_eid が残る)が残る。`docker restart` の後は、同じ読み込みが 110 秒で通った(1 回)。なぜ JVM に溜まるかは未確定(2026-11-19・決351 EC2 手元の演習の失敗の形 ③④⑤⑥-b と調べの回 r1)。

**ヒープ 512m(EC2 の B と同じ値・coord が 11-19 に読んだ)では、起こしたばかりの JVM の 1 度目でも外れる**(r2・378 秒・辺 41,379/46,793 で巻き戻し・後のヒープ 508/512 MB)。書き出し(export_graph_apoc の driver の形)は値を問いの文に直に埋め(UNWIND [ … ] が 94 本・最大 約 820 万字・束の既定 1,000 行)、長い文を読み解くのに大きなヒープを使う(推定)。

r3(11-19〜20・rep 20261120-0138)で 5 つの道を測った。ヒープ 1G と 768m は、読み込みの前に起こし直せば形 1〜3 とも通った(768m は後のヒープ 687/768 MB で余りが小さい)。512m のまま束を小さくする 2 つ(100 行・1 本 100 万字まで)は、どちらも初めの読み込みで外れた。512m のまま、止めた DB に neo4j-admin で dump を戻す道は、通った(戻し 約 4.5 秒・ヒープに依らない)。ヒープ切れになった JVM に状態を問うと、応答が返らない(r3 が 2 時間 20 分止まった)。外れた後は、起こし直してから問い、上限も置く。

**Why:** EC2 の B は 512m なので、今の計画のままでは当日の W5 と復旧の読み込みが外れる見込み。推しは dump を戻す道で、coord の決めを待つ(11-20)。

**How to apply:** 同じ容器に大きな読み込みを何度も入れる手順・演習では、読み込みの前に B を起こし直すか、回数を数える。外れの札は Neo4j の誤りの札ではなく rc1 だけなので、stderr を私的な置き場に残して形を見る。案 甲(読み込みの前に起こし直す)は 11-19 に coord へ諮った(rep 20261119-2218)。
