2026-09-23、V3 案 B の段 B9-a で「要求全体の上限(組の数)」の正式値を測った。実在の 11 問の最大は 54 組。そこへ bkb が作った合成質問(設備名を並べただけ)が 120 組出たので、私は測定報告に「いまの 90 では足りない」と書き、**144 を案として出した**(120 ちょうどだと 1 語増えて 422 になるから、という理由)。coord は 120 を採った(決19-1)。

その後 bkb が、**同じ辞書から語を増やすだけで 144 / 372 / 744 / 1,464 / 5,928 / 8,892 組を作れる**と実測した。利用者の決定は **90 のまま**。承認の一枚の「全質問の Plan の最大以上」は「**実在の質問集合**の最大に余裕を見た値」と読み、合成質問は**上限で止める対象**だった。決19-1 は撤回された。

**Why:** 上限は「壊れた要求を止めて、絞る材料を返す」ための門である。止めたい入力に合わせて値を上げると門が素通りになる。しかも入力が合成できる領域では「観測した最大」に上限が無く、測るたびに値が上がる。私は「推定を実測と混ぜない」を守ったつもりで、**測った値だから正しい**と扱ったが、**測れる最大が有界かどうかを確かめていなかった**。同じ報告の §9 に「13 問の代表性は確かめていない」と自分で書いており、その限定は §6 の推しを否定していたのに、照らさなかった。

**How to apply:**
- **閾値を出す前に「これは何を守る門か」を 1 行書く。** 値は守る対象(実在の入力・SLO・費用)から導き、**観測した最大の入力からは導かない**。
- **入力が合成できるなら「最大」は無い。** 「全部の入力の最大以上」と書かれた規則を読むときは、**その『全部』が固定された集合かどうかを先に確かめる**(固定されていなければ、規則がまだ決まっていないということ)。
- **門を超えた入力に逃げ道(422 の本文・絞る材料)が契約として在るなら、超えること自体は異常ではない。** 「超えた例が出た = 上げるべき」ではない。
- **推しを書いたら、同じ文書の限定の節を読み返す。** 限定が推しを否定していたら、推しの方を直す([[recommendation-must-fit-own-premises]])。
