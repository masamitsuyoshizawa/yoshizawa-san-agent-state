**判定の基準を、使う道具の出力の形で書くと、道具の都合が基準に入り込む。**

2026-09-18、B-KB の測定で「X と Y の質問文の差が、半角併記の付加分だけであること」を確かめる基準を、`difflib.SequenceMatcher` の返す区間で組み立てた。「1 区間の `insert` であること」「区間の内容が付加分と byte 一致すること」「2 区間以上なら中止」。

**区間はアライメント依存で、判定の根拠にできない。** 併記はどれも `" / "` で始まるので、挿入点が複数通りに書ける。総当たり 867,591 通りで両方の破れを確認した。

| 現象 | 件数 | 最小の例 |
|---|---:|---|
| **1 区間だが内容が付加分と違う** | 16,587 | `hw=" / A"`・`rest=" / B"` → 区間の内容が `"A / "`(3 字ずれ) |
| **正しい状態なのに 2 区間** | 4,437 | `hw=" / A"`・`rest=" / AA"` → `insert " / "` と `insert "A"` |

2 つ目は**正しい試行を中止にする**。

**正しい書き方は、位置を明示した恒等式**だった:

```
X == q0 + 付加分 + Y[len(q0):]
```

アライメントに依らず、付加分が空の場合(`X == Y`)も同じ式で覆える。

**Why:** レビュー側の要求は「挿入された中身を確かめる」で、それは恒等式で直接書けた。道具(`SequenceMatcher`)を先に決めたので、基準がその出力の形に縛られた。**順序が逆だった。**

**How to apply:**
- **要求を言葉にしてから、それを直接表す式を書く。** 道具はその式を検算するために選ぶ。
- **道具の出力(区間・スコア・順位)を判定の条件にしない。記録に残す。** 判定が偽になったとき「どこが違ったか」を書くために要る。
- **道具に「同じものを別の形で返す自由」があるかを確かめる。** アライメント・タイブレーク・浮動小数の表現などは、同じ入力に複数の正しい出力がある。
- **実装して実データに当たるまで出ない**([[spec-unverified-until-implemented]])。この欠陥も、他セッションが実装して 3 問中 1 問で見つけた。

**同じ型を 2026-09-21 の 1 日で 4 件やった。いずれも「自分が作った表示・自分が呼んだ道具の出力」を、確かめずに事実として扱った。**
1. 語を「・」で分割して 11 語しか拾えていないのに「19 語すべて confirmed」と書きかけた(母数を見ていない)
2. `git check-ignore ... | head -1; echo "rc=$?"` と書き、パイプの `head` の rc を拾った。`fatal`(rc=128)が「rc=0」と表示された
3. Counter の表示で自分が `'|'.join(source)` と書いたものを見て、「source は区切り文字で連結した文字列」とデータの形を誤読した(実際は全件 list)。**この誤りは他セッションの設計書の入力に採られ、急いで訂正した**
4. コミットメッセージを `printf` に渡し、本文の `46.2%` の `%` で切れた。`Co-Authored-By` ごと落ちたのに、**件名だけ読み返して気づかなかった**

**How to apply(追加):**
- **型を出す。** `type()` / `isinstance` の結果を一度表示してから、形について書く。表示用に加工した文字列は「表示」であって中身ではない。
- **パイプの先の `$?` は最後のコマンドのもの。** 終了コードを見るならパイプを外すか `PIPESTATUS` を使う。
- **`printf` に本文を渡さない。** 連絡文と同じく Python から渡す(`%` も `\` も壊れる)。
- **読み返すのは末尾まで。** 件名だけでは本文の欠落は分からない。`git log -1 --format=%B` の行数と最終行を見る。

**終了値は「確かめていない」を「成功」に化けさせる(bkb・2026-09-21)。** 試験の `main()` が `return 1 if ng else 0` と書かれていると、**不合格 0・未検査 1 が `rc=0`** になる。表示には「未検査 1 件」と出るが、`rc` だけを見る呼び手には届かない。実測: 辞書を参照する試験を、辞書の無い場所へ複製して回すと `(None, None, None)` で SKIP し、**何も照合していないのに `rc=0`** だった。**本体ツリーからしか回していない書き手は自分では踏まない — 踏むのは呼ぶ場所が違う人である。** 是正は `0 = 不合格 0 かつ未検査 0` / `1 = 不合格` / `2 = 未検査`。**1 と 2 を分けるのは「壊れている」と「確かめていない」で対処が違うから。** 呼び手の側に「未検査の数を見る」契約を置く案は採らなかった — **契約を知らない呼び手が必ず現れる**。門を足したら、SKIP を 1 つ注入して実際に `rc=2` が出ることを走らせて見る。
