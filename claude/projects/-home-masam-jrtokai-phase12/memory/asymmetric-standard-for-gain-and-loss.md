指標が上がったときは寄与を切り分けて割り引くのに、下がったときは「測定のゆらぎ」として落とす — 同じ量に二重の基準を当てないこと。

B-KB の (1)(半角併記)撤去で、述語 Recall の一致(ids まで byte 同一)を根拠に「劣化は無い」と報告したが、顧客に届く `LIMIT` 込みの値は 3 問で −25〜−40 ポイント下がっていた。自分は直前に「`LIMIT` 込みを単独で効果として読んではいけない」に同意し、自分でも測って示していながら、劣化の側には同じ規律を当てていなかった。

**Why:** 非対称な基準は、望む結論の側にだけ厳しさを緩める。当人には一貫して見えるので内部からは崩せない。この件は coord・fed・bkb の 3 者が同じ見落としをし、外部レビュー(rev)の指摘で初めて露見した。

**同じ根から出る別の形: 自分の案に有利な側で断定が強くなる。** 2026-09-19、2 つの測定方式を比べる設計で「他方は再起動が要るので実行順の交互化が**できない**」と書いた。実際には再起動は**費用**であって不能ではなく、対照は組める。自分の案(同一プロセスでの切替)を通す方向に言葉を強くしていた。rev に「それを唯一の成立方法としない」と指摘された。**費用・手間の問題を不能の問題として書いていないか**を、案を推す文では特に確かめる。

**How to apply:** 変更の可否を数値で論じるときは、(a) 顧客・利用者に実際に届く指標を主指標にする(内部指標は併記に留める)、(b) 上昇と低下に同じ割り引き方を当てる、(c) 中止条件に顧客側の指標を必ず入れる、(d) 「幅で測るもの」と「1 件でも起きたら止めるもの(門)」を混ぜない。平均は判定に使わない — 個別の問いの大きな低下が平均では埋もれる。
