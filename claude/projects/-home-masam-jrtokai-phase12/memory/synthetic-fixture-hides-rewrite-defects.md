合成の文書で通しの演習を何十回回しても、`census/masking_report.json`(ingest_one が mask_preprocess を報告の置き場の指定なしで呼び、その回の文書の分だけで上書きする)が守りの道具の表から漏れていたことに気づかなかった。合成の文書は氏名の当たりが無く、報告がいつも空 `{}` で中身が変わらなかったため。台を作り直して初回にファイルが無かったときに、たまたま T1 の外れとして現れた。実際の文書なら全ジョブが T1 で GUARD_MISMATCH になっていた(推定)。是正 = 816ad4384(K-2a.3 の追補)。

**Why:** 「その回の分だけで上書き」の欄は、入力が毎回同じだと前後で同じになり、比べの外れが出ない。演習の合成の値が本番の入力の性質(当たりの有無・名の違い)を欠くと、上書きの型の欠陥は隠れる。

**How to apply:** 守りや比べの受入では、(1) 道筋の道具が書くファイルを grep で洗い出し、表と突き合わせる(現れた外れを待たない)(2) 合成の入力に本番と同じ「当たり」を持たせる(氏名・地名の当たり・行のある要確認の一覧など)(3) 前の回と違う中身になる対照を 1 本置く。関連: [[spec-unverified-until-implemented]] [[snapshot-compare-needs-health-and-plan]]

追記(2026-11-09・dkb・決352 段 2): 層化の道具の試験の合成の目録で ext を「.xlsm」(点つき)にしていたが、段 0 の目録の実物は「xlsm」(点なし)。道具も点つきで比べていたので試験は通り、実物で回して初めて xlsm の被覆 0 に気づいた。**合成の入力の欄の形は、実物の目録の値を数えてから作る**。同じ日に、主張が `or True` で何も確かめていない試験も書いていた(強めたら道具の二重選択の誤りが出た)。
