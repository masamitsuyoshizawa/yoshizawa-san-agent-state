照らしの道具(位置の対応を追う検査など)は、合成の反例の試験が全部通っても、本物の値に当てると壊れていることがある。使う前に、本物の値で次の 3 つを当てる。

1. 何も変えない値(前 = 後)に当てて、落ちるべき所が落ち、対応が取れない所が 0 か
2. 書き手の計画を手元で当てた「正しい後の値」に当てて、合格するか
3. その値に変異(再び伏せる・取り違える)を 1 つ入れて、その 1 つだけを落とすか

**Why:** 決351 追補 19(2026-11-13)で、rev の要是正に応えて W4 に位置の照らし(align)を足した。合成の反例 7 件は全部通ったが、正本どうしに当てると 231 行で対応が取れなかった(続く札を 1 字ずつ比べ、近くの戻した語の分ずれていた)。合成の入力は短く、近くに別の戻した語が無かった。同じ便で、新しい試験の数を 35 と申告したが、内訳の足し算は 32 だった(rev が構文木で数えて見つけた)。

**How to apply:** 照らしの道具を rev に出す前・台で使う前に、上の 3 つを B 正本(読むだけ・LOCKS)で回し、数を rep に書く。申告する数(試験の件数など)は、内訳から足し直してから書く。[[synthetic-fixture-hides-rewrite-defects]] [[negative-test-check-reason]]

2026-11-13 追記(rev 再確認): 位置の対応を「続きが合う最短の 1 つ」で選ぶと、近くに同じ語が繰り返すとき、消えた区間を区間の外の同じ語に当てて偽の合格になる。**対応が複数ありうる照らしは、許される対応を全部見て(帯の中の前後の到達で)、悪い側の対応が 1 つでも在れば合格にしない**(align_all・固定版 64adc369d)。

2026-11-13 追記(rev 3 回目): 探索に固定の上限(連なり 32 字)を置くと、上限を越える経路だけが外れて偽の合格になる。**上限は守る対象の構造から導く**(帯 D の中では連なりは D+1 に自然に限られる = 固定の上限は要らない)。固定版 7587bc02f・本物の B で時間は変わらず 3.5 秒。

2026-11-13 追記(rev 5 回目): 出現を re.finditer で数えると互いに重なる出現を数えず、「1 回に決まる」を誤る。**一意さの判断に使う出現の数は、重なる始まりも全部数える**。また「照らせない 0」は、欠け・型の不正・解析の失敗を照らせないとして数えて初めて意味を持つ(空の並びや空文字の一致にしない・照らした数 0 も不合格)。

2026-11-13 追記(rev 7 回目): 前後の値を照らすとき、取り出した並びの位置で対にすると、数が同じでも別の物どうしを比べる(鍵の入れ替えで空への変化が隠れた)。**前後の対は、取り出す元の道筋(鍵と位置)を印にして作り、片側にだけ在る物は照らせないにする**。また仕様を他者へ渡すときは「固定データで 0 件」という前提と「コードの決まり」を分けて書く(*_masked を「触らない」と書いて訂正した)。

2026-11-14 追記(rev 13 回目): 利用者の判断を道具に入れるときは、(1) 判断を受けた時の対象の位置を、判じた時の道具で記録して固定する(後で形の判定を直しても、承認の範囲が広がらない)、(2) 判じた一覧は sha16 と答えの欄の外の全セルの指紋で照らす(行のずれ・入れ替え・重複を止める)、(3) 対をたどるのは唯一の対応の同じ番目の印だけ。JSON の値の形の判定は、生の文字列でなく展開した葉で(エスケープの 2 字を空白や改行と見なさない)。
