決365 1-1 の読みの台本で、rev に 2 度(2150・2251)不可とされた指摘は、全部が 2 つの型だった: (1)「失敗」と「無い」と「0」の取り違え(inspect の失敗を不在に・容器が途中で消えても完了・find の失敗を捨てて部分の件数を確定・欠測を 0 に読み替え)、(2) 平文で残る値(起動の引数・字の種と長さだけ照らした値・秘密のファイルを開く)。個々の所を塞ぐと、塞いでいない所を rev が次に見つける。coord の案(2026-11-23 22:54・決365 追補 17)で 2 つの決まりに組み直した(改訂 4・80e4aa811)。

**Why:** 決まりに対して試験を作れる(読みの一覧の全部に失敗を 1 つずつ注入して票が確定しない事を表で示す・手元の判じを全部の崩し方に当てる)。個別の塞ぎは、塞いだ所しか試験できない。段 A〜D(決351)でも同じ型の指摘が続いた。

**How to apply:**
- (ア) 遠隔のどの読みも、データを出してから印を 1 つだけ(ok <件数> / absent / fail:<番号>)。手元は読みの一覧(MANIFEST)を持ち、全部に印がそろい、件数と中身が合った時だけ確定。不在を許す読みは一覧に明示。管で終わりの値を失う所は終わりの値をデータと一緒に返す。
- (イ) 票の平文は、項目ごとに候補を列挙できる値だけ(真偽・数・決まった名)。ほかは一致の真偽だけ。件数で足りる物(秘密のファイル)は開かない。
- 試験 = 決まりに対して: 全部の読みへの注入の表(端から端まで)+ 手元の判じの崩し方の表(docker なし)+ 直す前の版への対照。
- 1-2 以後(管・持ち込み・戻し)や、別の読みの道具でも、最初からこの形で書く。関連: [[gate-allowlist-not-denylist]] / [[check-both-branches-of-a-condition]] / [[test-env-r365-plan]]
