**「これは私が書いた誤りです」も、確かめていなければ、ただの未検証の主張である。**

2026-09-21、共通表の理由「どの実装も返さない状態は試験できない」(rev が不正確と指摘)について、当方は「その理由は当方が `rep 1417` で書き、coord が写した」と申告した。**coord が現物で照合し、当該 `rep` に「試験」は 0 件、その文は coord の共通表 332 行目にしかなかった。** coord の言葉: 「自分の誤りを多めに引き取る申告も、確かめてから受けます」。

**ただし当方が `grep` したところ、記録には続きがあった** — 当方の `rep 1436` の summary と §3 に、同趣旨が当方の言葉で 2 か所あり、「あなたの理由と同じです」と明記して自分の理由としても採っていた。**正確な言い方は「出どころは coord・確かめずに採って言い換えた分が当方」で、どちらか一方ではなかった。**

**Why:** 帰属を誤ると、相手が監査台帳の記録を書き換えかねない。**記録が実際と違えば、次に同じ型を防ぐときに見る場所を間違える。** 謙譲の向きでも害は同じで、「多めに引き取る」ことは誠実さの表示にはならない。

**How to apply:**
- **「私が書いた」「あなたが書いた」を書く前に `grep` する。** 自分のツリーの過去の版は `git show <sha>:<path>` で読める(落ちた行の追跡に有効)。
- **経路が複数段あるときは、段ごとに在る/無いを表にする。** 「原因は当方」も「原因はあなた」も、途中の段を見ていない言い方になりやすい。
- **同趣旨の言い換えも数える。** 語が一致しなくても、自分の言葉で採って書いていれば、それは自分の記録である。
- **発信済みの連絡文は遡って直さない。** 訂正は新しい `rep` に書き、そこを記録とする。

同じ日に同型を 2 回: `rep 1436` §6 で「文書内に『顧客の要求』『顧客の回答』はありません」と書き、打ち消しの形で 2 か所あったのを見落とした。どちらも**自分の文書についての主張を、文書を検索せずに書いた**。

**名の出どころも帰属である(2026-09-24)。** S4-F の読み手で理由の札 `unknown_property` を「設計書の名」とコード注記・rep・info の 3 か所に書いたが、設計書に 0 件で、出どころは fed 自身の計画だった。coord の決定文はこれを受けて閉じた一覧を「fed の 7」で数え、1 つ落ちた。**名・定数・規則を「どの文書由来か」で分類するときは、その文書を名で grep し、分類を機械検査にする**(D5: 読み手が出す札を構文で集めて一覧と両向き照合・設計書側は設計書に名が在ることを見る)。
