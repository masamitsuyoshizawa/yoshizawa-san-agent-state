2026-10-05、作業用の場所(/tmp の scratchpad)の接続設定のファイルが再起動で消え、稼働中のコンテナから作り直したとき D-KG と B だけを入れ C-KG(9990)を入れなかった。diagnose の C 系の接地は `except Exception: g = []` で失敗を握りつぶし、「C系実設備への接地なし」と書くだけなので、E2 で 10-02 の写しと 62/1,345 件が違い、coord に「データの状態の変化と見ている」と誤って報告した。C を足すと 1,636 件すべて byte 同一。

**Why:** 握りつぶしは、作業環境の欠けを「データの変化」に化けさせる([[silent-path-drift-masks-cause]] と同じ型)。digest が記録と同じなら、データ以外(接続・環境変数・旗)を先に疑う。

**How to apply:** 接続設定を作り直したら、B・D-KG・C(KG_C_URI/KG_C_PW)・語彙 DB を揃え、比較の前に 4 つへ繋がることを 1 行ずつ確かめる。比較で差が出たら、原因を書く前に「前の版のコードを今の環境で回す」と「digest を記録と照らす」で、コード・データ・環境を切り分ける。原因が確かめられていないうちは「未確認」と書き、推定の向きも書かない。
