2026-09-24、T0 の図の受入検査 R4-b で「原文と 8 字以上一致しても、出どころが出してよい name だけなら許容」を `origin_of.get(text, set()) <= {"name"}` と書いた。**期待に無い文字列(差し込まれた原文)は出どころが空集合で、空集合はどの集合の部分集合でもあるので許容に落ちた。** 正常な図では期待外の文字列が 0 件なので、実データでは一度も表に出ない。**否定例(standard の文を差し込む)を書いて初めて見つかった。**

**Why:** 部分集合の判定は「すべての要素が〜」の形で、要素が無ければ真になる(空の全称)。許容・合格の判定を「全部が良い側」で書くと、対象が空のとき黙って通る。

**How to apply:** 許容や合格を `all(...)` や `<=` で書いたら、**対象が空の場合にどちらへ落ちるかを 1 行で決めて書く**(許容なら「空でなく、かつ全部が〜」)。否定例には「期待に無いものを差し込む」を必ず 1 つ入れる。関連: [[negative-test-check-reason]]・[[claim-wider-than-implementation]]
