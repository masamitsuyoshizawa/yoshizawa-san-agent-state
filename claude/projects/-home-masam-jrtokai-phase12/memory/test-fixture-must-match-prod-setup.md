一括追加 7a の試験(bkb の持ち物)が、本体ツリーでは毎回落ち、作業ツリーと一時の木では合格していた。偽のジョブを input/ だけで作り、本番の worker が事前の照らしの前に必ず通す init_state(.internal/ を作る)を通していなかった。データ置き場と補完辞書の写しが在る木では既存の名の検査を通って .internal/stem.json の書き込みで落ち、無い木では手前の別の札で止まり、R2 の判じ方「3 つの札以外なら合格」が両方を通した。dkb が仕組みを見つけた(info 20261118-1311)。直しは試験だけ(9b35f3a1b): init_state で作る・一時の工程の置き場で検査を差し替える・合成の補完辞書・行き先の札まで決める・差し替えた検査が呼ばれた数を照らす。

**Why:** 試験の台が本番の作りと違うと、本番に無い失敗(試験だけの欠陥)や、本番の欠陥の見逃しが起きる。弱い判じ方は、どの道を通ったかを隠す。11-11 の本物の資格の門の件と同じ型(coord)。

**How to apply:** 試験の偽の物は、本番が同じ物を作る関数(init_state など)で作る。判じ方は「この札以外」でなく、行き先の札と書かれた物まで決める。木のデータ・補完辞書・本物の工程の置き場で道が変わりうる試験は、一時の置き場と合成の入力で道を固定し、差し替えた部品が呼ばれた数も照らす。直したら、init_state を外す対照で、どの木でも深い道を通ることを確かめる。関連 [[test-must-not-inject-what-prod-lacks]] [[synthetic-fixture-hides-rewrite-defects]]。
