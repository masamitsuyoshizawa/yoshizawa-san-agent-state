連絡文の `re:` に書くファイル名を、**相手の文面の話題から組み立てて**書いていた。自分発 83 通を走査したところ **26 件(31%)が実在しない名前**だった(例: `20260918-2030_dkb_to_ckb_rep_kindword-signal.md` と書いたが実物は `..._rep_class-word-contradiction.md`)。日時は合っていて slug だけ違うので気づきにくい。

**この型は `re:` に限らない。** 2026-09-19 の 1 日で 5 件やった。
1. `re:` の slug を話題から組み立て(実物と違う)— 書く前の `ls` で捕捉
2. 同上(別便)— 同じく `ls` で捕捉
3. `LOCKS` を解放するとき、予約行の開始時刻を「たぶん 15:29」と書いた(実物 15:28)— 置換対象が 0 箇所になって捕捉
4. コミットメッセージに自分の便名を `rep 1547` と書いた(実物 1541)— 直後に気づき `--amend`
5. 同上 `rep 1608`(実物 1607)— 同じく `--amend`

**Why:** 相手の連絡の「中身」は会話で受け取っているため、識別子も分かった気になる。**自分が数分前に作った便名や時刻でも同じ**ことが起きる — 覚えているつもりで、実物を見ていない。

**同じ型は「節番号・項番号」でも起きる。** 2026-09-21 に 2 件。
- 他文書の「索1〜索4」を §1-14 にあると書いた(実物は §1-6)。**§1-14 の表の中に「索」の語が出てくる**ので、そこに定義があると思い込んだ — 引く先の節を開いていない。
- 「共通表 §1-12 の 7 と同じ型」と書いた(実物は 8)。7 は別の規則で、**直前に別の箇所で 7 を引いていたので、その番号をそのまま使った**。

**番号まで書く参照は、その番号の行を開き、自分の文とその行が同じことを言っているかを照合してから書く。**「同じ型」「同様に」と書きたくなったときは、たいてい**当てはまる番号が別に在る**。文書を出す前に、番号付き参照を全件 grep して 1 つずつ本文と突き合わせる(2026-09-21 に 8 か所やり、1 件の誤りが出た)。

**「誰が測ったか」も識別子である(2026-09-21・fed)。** 共通表の数の出所を `rep` に「coord と dkb の測定です」と書いたが、実物は **rev と coord** だった。**数そのものは合っていたので、自分では気づけない** — 相手(coord)が訂正した。**その取り組みに dkb が居て、直前に dkb の測定を引いていたので、そのまま並べた**。確かめる手段(`docs/review_rev/` と連絡文)は手元にあった。**出所を人の名前で書くときは、その人の成果物を開いてから書く。** 「確度」や「未検算」の表に出所を並べるときほど、**自分が検算していない値なので、誰の値かが唯一の担保**になる。

**`sha` は「いつ採ったか」も識別子である(2026-09-22・bkb)。** 連絡文に `v3_response_checks.py` の sha16 を `57813524bdc29579`・340 行と書いたが、コミットの blob は `75e09d1d1559d93c`・341 行だった。**原因は、報告のために sha を採った後で、その連絡文の名前を注記へ入れる 1 行を足したこと。** 申告と現物が 1 行ずれた。**同じ便の中で「版を採る」と「本文を書く」を往復すると必ず起きる** — 本文を書く行為がファイルを変えるため。coord が `git show` で照合して見つけた。**ファイルの版を報告するときは、最後の編集を終えてから採る。コミットした後なら `git show <コミット>:<パス> | sha256sum` で採る**(作業ファイルからではなく)。

**How to apply:**
- 他の文書を指す識別子は、書く前に実物から取る。`ls docs/comms/ | grep <日時>` / `sed -n '<行>p'` / `git log -1 --format=%B`。
- **自分のファイルの `sha`・行数は、コミット後に `git show <コミット>:<パス>` から採る。** 作業ファイルから採った値は、その後の 1 行の追記で古くなる。
- **置換するときは「1 箇所であること」を assert する。** 0 箇所で止まれば、組み立てた識別子の誤りがその場で分かる(3 はこれで捕まった)。
- **書いた直後に grep で数える。** コミットメッセージは `git log -1` を読み返す(4・5 はこれを省いて後から気づいた)。
- **一括置換で直そうとしない** — 同じ日時に複数の連絡があり、「ckb を含むものを優先」のような当て推量は誤った対象を選ぶ(2026-09-19 に実際に誤り、`git checkout` で戻した)。直すときは 1 件ずつ `to:`/`from:`/`type:` を読んで確かめる。
