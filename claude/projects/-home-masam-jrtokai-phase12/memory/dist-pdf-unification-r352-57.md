利用者の方針(2026-11-16): 新しい事故摘録は、個人情報の処理と構造化の分析の後に、閲覧・配布と SAT 登録を兼ねる「展開用のファイル」を作り、形を PDF にそろえる。coord の見立て = 採る(条件つき)。決352 の dec の追補 57(main 007b58aed)・決359 追補 8・bkb への依頼 req 20261116-1535_coord_to_bkb_req_dist-pdf-unification-design.md。

**Why:** MCP の閲覧の口は PDF を inline・Excel は attachment(確定)。SAT の既定の道(Excel→PDF)は隠しのシートも頁にし、書式の無い xlsx は字が切れる(決349 追補 4・6)。出典の頁が、利用者が開く PDF の頁と同じになる。

**How to apply:**
- 条件: (1) PDF は伏せた原文(セルの値)から決定論で作る・LLM の抽出の結果から作らない・構造化の結果は載せない (2) 値だけの xlsx は配らない内部の中間物として残す(bkb の照らしを生かす・Excel 原本の PDF は案 C = セルの位置と結合から表) (3) 字形は使う字だけ・属性は空・毎回同じバイト列・pdfplumber の読み直しで字の切れ 0・8 MiB (4) 頭に「作り直した閲覧用・図と写真は含まない」(5) 様式を固める前に架空の PDF で SAT の取り込みを試す (6) 対応表は形に依らない作りのまま。
- 利用者の理由のうち直しが要る点: SAT は PDF を受けた後も生成 AI が頁を読み直す(架空の PDF 1 件で、手元の pdfplumber は正しく読めるのに SAT の本文は表に組み直され英字に空白)。PDF の出来を決めても、この段は残る。
- エージェントのデモは SAT の検索の結果をファイル名で手元の索引に結び付ける(incident_vector_search.py の normalize_incident_file_key・写し 2026-10-28 の版)。acc 番号の名で入れ直すと外れる → SAT 登録の段の前に名の決まりを確かめる。
- 利用者の承認(2026-11-16・決352 追補 59): 条件 (1)・(2)・(5) の 3 点とも承認。
- **形の選び(決352 追補 60・架空の PDF の試し・各 1 件 1 回)**: Excel が原本の物 = 段落の形(1 行ごとに「項目: 内容」)・PDF が原本の物 = 今の build_pdf の形・SAT の設定 = 既定(gemini・pdfplumber)。既定の設定では、表でない頁は PDF の字の層がそのまま SAT の本文になる(確かめの語 6/6・100%)。表の形は既定でも生成 AI の書き写し(5/6・86.2%・1 字の取り違え)。vlm_with_table_context は表でない頁も読み直す(段落の形で 4/6)。→「PDF の出来を決めれば確か」は、形を選べば成り立つ。
