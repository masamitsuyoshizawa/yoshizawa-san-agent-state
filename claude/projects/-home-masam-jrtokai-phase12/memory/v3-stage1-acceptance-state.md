## 設計上いちばん効いた 3 つ

1. **件数の検査は、応答の中だけでは閉じない。** `returned == min(limit, total_matched)` を置いても、`total_matched` を過少に申告されると `returned` もそれに合わせて小さくなり、すべての式が通る。**API の外で独立に数えた全一致の集合 `E` との照合(件5・件6)が要る。** 「完全性の条件 = `returned == total_matched`」は**自己整合の条件でしかなかった**。
2. **0 件の検査は合格ではない。** 「返った各事故に由来がある」は `results` が空なら空虚に真。デモの門が `error` を通す穴もこれで開いていた。**対象 0 件は「未検査」と記録する**(共通表の一般の規則へ採用)。
3. **既定でない要求も検証する。** gold の組を `groupings` の既定に連動させると、既定でない側の誤りが見えない。**提供する 3 切り口 × 2 `grouping` = 6 組で固定**し、既定は契約の検査(契1〜契3)へ分けた。
