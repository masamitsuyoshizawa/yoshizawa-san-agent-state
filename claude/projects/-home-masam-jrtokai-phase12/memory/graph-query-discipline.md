**グラフの到達数・接地数を報告するときの規律(2026-09-15・dkb 発案、coord が COORDINATOR.md に採用)。**

1. **到達数は必ず 2 つ並べる。**「無向・型無制限(上限)」と「型限定・向き固定(実効)」。1 つだけ出すと読む側は有向だと思い込む。
2. **逆行を使う場合は型ごとに `<-[:X]-` と式に書き、報告にも「逆行 N 回」と書く。**
3. **端点に接する型を列挙してから経路を定義する。** `-[]-` や `-[*1..2]-` を書きたくなった時点で、型を列挙していないという合図。
4. **1 本の経路として書くか、MATCH を分けるかを式とともに明示する。** Cypher の関係一意性は 1 つの MATCH パターン内でだけ効く。分けると同じ関係を再利用でき、同じ意図の式が別の集合を返す(1 本の経路 155 症状 / MATCH 分割 175 症状 = 2a ∪ 2b)。規律 3 を守ってもこの差は防げない。

**実例(同じ誤りを dkb・coord・fed が各 3 回程度繰り返した)**:
- 無向 `-[*1..3]-` で「症状 864 が検査に到達」と報告 → 型限定・向き固定では 200。差は数え方でなく向きだった。
- 「検査→測定基準 579・6 段が現状で通る」→ `FieldCheck` は出次数 0 のシンクで、有向では 0。579 は逆行の産物。
- 「部品へ結ぶと測定基準へ届かない」と書きかけた → 型を列挙すると `<-[:HAS_PART]- EquipmentType -[:HAS_MEASUREMENT]->` で全 1,565 件届く。
- 他者の値との差を「数え方の違い」で片付け、自分の式が無向であることを確かめなかった。
- 集計スクリプトの注記に「型限定の実効値」と書きながら式の後半が `-[*1..2]-` だった。
- **関係の本数と相手の件数を取り違えた**: 原因→測定基準の逆読みの最大が `count(r)` で 16、`count(DISTINCT y)` で 8。同じ測定基準が同じ原因へ `SUPPORTS_IF_ABNORMAL` と `CONTRADICTS_IF_NORMAL` の 2 本を必ず張るため本数が 2 倍になる(`OUT_OF_RANGE_IMPLIES` も 220 と 143)。**分岐や上限の議論では相手の件数を使い、どちらで数えたかを書く。**
- **型名から意味を推測すると逆に読む**: `DETECTED_BY_FIELD` は「検知」ではなく**除外実績**(切り分け記録の `excluded` から投入・「この確認でその原因概念を除外できた」)。`SUPPORTED_BY_FIELD` は `suspected`(疑った対象)。辺の `basis`(`det` / `llm_high`)は原文照合の有無ではなく**除外語・疑い語を概念へ寄せた方法**。意味は投入コード(`ingest_isolation_knowledge.py`)と診断コードのコメントで確かめる。
- **件数で照合して出どころを誤推定した**: 「175 症状」が 2a ∪ 2b(分割 MATCH)と、概念を通らない別経路の和の両方で出たため、同じ集合と見なしかけた。要素で比べると共通 71・片側のみ 104 ずつで別物だった。**集合が同じかは件数でなく要素(elementId の集合)で比べる。**

- **関係の形を見ずに、辺の有無で群を判定した**(2026-09-26・B の重複取込): `DUPLICATE_OF` は**正本へ向かう星形**なので、**同じ群の 2 件の間に直接の辺は無い**。直接の辺で「既に同群か」を見て、既に束ねられている対を「人手の確認が要る」と報告した。**群・クラスタは連結成分で数える**(`apply_duplicate_of.py` の検証=相互参照 0・連鎖 0 では、この型は検出できない)。
- **出力を入力と取り違えた**(同日): `accident_twins.json` は検出器ではなく、**B の `DUPLICATE_OF` を書き出したもの**(`build_twins.py`)。「ファイルに無いから検出が漏れた」と書いたが、ファイルとグラフは定義上一致する。**比較の前に、その資料がグラフの入力か出力かを確かめる**(出力と比べると自分自身との比較になる)。

- **測っていない軸で規約を書いた**(2026-09-21・V3 語彙 DB の設計): 展開の安全弁を「深さ 10」とし、根拠に `parent` の深さの実測(最大 4)を挙げた。**`SYNONYM_OF` の連結性は測っていなかった**。測り直すと連結成分 798 個・**最大 141 語・直径 4 段**で、**141 語すべてが深さ 10 以内**。**安全弁は 1 語も止めない**。**広がりは深さでなく連結成分の大きさで起きる** — 深さの上限は広がりを止めない。**閉包の守りは、止めたい量そのもの(成分の大きさ・返る語数)で書く。**
- **同じラベルに意味の違う辺が混ざると推移閉包が壊れる**(同日): `kind=variant` に「表記ゆれ」(`軌道回路設備`)と「修飾のついた具体例」(`31T軌道回路`)が同居。正準名「軌道回路」が個別の軌道回路名を 112 件 `variant` として持つため、両方向・推移的にたどると `31T軌道回路 ≡ 軌道回路 ≡ 津RH軌道回路` が導かれる。**辺の型を関係の型へ写す前に、その型の中身が 1 つの意味かを実データで見る**(一般名に付く辺の次数を数えると露見する)。

**Why:** 注意では防げなかった。照会の書き方に規律が無いことの問題で、型を列挙する手順を先に置くと `-[]-` を書く余地が消える。
**How to apply:** D-KG / B の照会で到達・接地を数える前に、端点ラベルに接する型を向きつきで列挙する(`MATCH (n:L)-[x]-(o) RETURN type(x), 向き, labels(o), count(*)`)。報告には上限と実効を並べ、式を添える。集計は `knowledge_kb_v8/scripts/dkg/ft_inventory.py` が規律に沿った出力をする。関連: [[verify-in-separate-process]] [[ingest-effect-unmeasured]] [[estimates-not-labeled-as-measurements]]
