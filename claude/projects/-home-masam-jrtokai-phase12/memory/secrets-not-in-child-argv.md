検査の道具が子プロセスを起こすとき、鍵・パスワード・照らす秘密の一覧を**起動の引数(argv)に載せない**。標準入力の pipe で渡し、子は真偽だけを返す。子の失敗や時間切れの報告に子の出力(標準出力・標準エラー)を写さない。

**Why:** 2026-11-11、dkb の screen-check が台の鍵と一時の DB のパスワードを json にして子の argv に載せ、rev の第 3 便で R352F-8(高)になった。argv は同じ機械の他の利用者から ps で見える。「秘密が表示に出ないか」を照らす道具自身が、秘密を argv に置いていた。サーバーの argv だけを照らして、自分の子を照らしていなかった。

**How to apply:** 子を起こす道具を書くとき、`subprocess.run([... , json.dumps(secret)])` の形を作らない(`input=` で渡す)。秘密を扱う照らしの試験には、合成の識別の文字列で「子の引数・報告に出ない・標準入力には在る(対照)」を正常・失敗・時間切れで照らす反例を足す。[[observation-lines-leak-names]] [[negative-test-check-reason]]

- 2026-11-11 の続き(rev 第 4 便 R352F-9): 検査の子の**終了コードを合否に使う**。子が非 0 で終わっても出力の形が正しければ合格にしていた。反例は「出力は全部真のまま終了コードだけ非 0」の形で作る(終了コードと読めない出力を同時に返す反例では、この取りこぼしを捕まえられない)。標準入力へ書けない(BrokenPipeError)と、出力つきの時間切れも照らす。
