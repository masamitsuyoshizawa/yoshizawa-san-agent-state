**連絡箱(`docs/comms/`)のファイル名と `date:` ヘッダは、`date` コマンドの実時刻をそのまま使う。**

**2026-09-18 の 1 セッションで 3 回、実時刻より 1〜5 分先の値を書いた**(`0335`→実 `0330`、`1508`→実 `1507`、`1930`→実 `1925`)。**いずれも `date` を同じコマンドの中で実行しておきながら、本文を書くときに手で打ち直して先行させた。**

**なぜ悪いか**: **この連絡箱は過去に実時刻より最大 11 日先へ進んだ実績があり、`comms_unread.py` の [6/6] が「先の日付」を検出する**。**過去の分は `re:` の参照が壊れるため遡って直さない規約なので、先行した分はそのまま残る。** **1 通ごとは数分でも、同じ癖が続けば同じ事故になる。**

**How to apply:**
- **`date "+%Y%m%d-%H%M"` の出力を、そのままファイル名と `date:` ヘッダへ写す**(暗算しない・切り上げない)。
- **長い連絡文を書いている間に時刻が進むので、書き終えてから採る**。書き始めに採った値は、投函時に実時刻と比べる。
- **先行に気づいたら、その場で `git mv` + ヘッダの修正をする**(**投函直後なら `re:` の参照はまだ無いので直せる**)。
- **`python3 scripts/comms_unread.py` の [6/6] は「先の日付」を出すが、既存の 249 件に埋もれて自分の 1 件は目立たない**。**投函時に自分で確かめる。**
