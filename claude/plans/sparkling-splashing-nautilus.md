## 2. 型: 事例報告の言及(契約 v0.9・事例報告だけ・前の版も同じ型で受ける)

| 物 | 形 |
|---|---|
| 節点 `Mention` | `mention_type`(event・observation・check・finding・cause_candidate・judgment・countermeasure・equipment)・`value`(逐語)・`src`(単位と範囲)・`stance`(確定・推定・調査中・意見・否定 = 言い回しの表で決定論・表に無い時は空と印)・`stance_cue_raw` と位置・`measure_kind`(応急・恒久・再発防止・対策だけ)・`section`(8 つ)・`time_raw`・欄ごとの `basis`(llm・det・human) |
| 辺 | `(Case)-[:MENTIONS]->(Mention)`。言及どうし `LED_TO`・`EVIDENCE_FOR`・`RULED_OUT_BY`・`RESULTED_IN`(対策 → 観測か分かった事)は原文に明記の物だけで根拠の位置つき。欄の層と同じ事柄は `SAME_AS_FIELD`(決定論) |
| 画像 | 画像 1 枚 = 1 単位(単位の id + 画像の sha16)。画像から取った言及は basis = llm と利用者の確かめの印。K2 は逐語で照らせない物として別に数える |
| 伏せ | dcr は送る時に社名の表(第 2 版)を当てる。K2 は今の `masked()` で照らす |
| 入力の検査 | I25(語と当てはまり: 立場は原因の候補と判断だけ・処置の段は対策だけ)・I26(辺の両端の型)・I27(根拠の逐語と、言い回しの表の版が `_meta` に在る) |

## 3. 口: 事象から引く(API 1.1・足すだけ・型の凍結の前に rev の審査)

- `GET /v1/event/lookup?q=<事象の文>`。答えは 3 つの区画に分け、区画ごとに状態と欠け(「資料に無い」と「まだ探していない」を分ける)を返す。

| 区画 | 中身 |
|---|---|
| (a) 似た事例 | 探す先 = 事例報告(欄と言及)と、作業標準の事故の例の節。並べ方 = 字の重なり(正規化した字の並びの BM25・決定論)と意味の近さ(BGE-M3・手元で計算・版を固定)を RRF(k = 60)で合わせ、同点は丸めた点と id で決める。事例ごとに、原因を段に分ける(欄の原因〔確からしさ〕/ 文中の候補〔確定・推定・調査中〕/ 外した候補〔否定〕・意見は別)。対策を処置の段ごとに。言及の鎖(きっかけ → 確かめ → 分かった事 → 対策)。当たった訳(重なった字・区画) |
| (b) 関わる手順 | その事例を事故の例に挙げている作業標準(日付と車両の一致 = 決定論・片方だけは「要確認」)と、事象と機器の言及の字で探した作業標準の項 |
| (c) 図面の機器 | 機器の言及の字と、図の中の機器(DrawingDevice の字・名称表の行の名)の一致。図面が無い所は not_searched(手繰りは図面の API の計画で別に) |

- LLM は探しにも並べにも使わない。埋め込みは手元のモデルで計算し、版(モデル名・版・指紋)を `meta.versions` に記す。ベクトルは git の外(`data/graph/embeddings/<ダイジェスト>/`)に置き、グラフのダイジェストが変われば作り直す。問いの時に外へは出ない(手元の計算・決158 の置き場の決まりのまま)。
- 人が 1 つずつ確かめた物と、型で当てた物は、refs で見分け、数を混ぜない(coord の添え)。
