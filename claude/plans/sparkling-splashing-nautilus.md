# 計画: 社名を伏せた 7 本の入れ替えに要る、投入の道具と API の直しと、入れ替えの演習(決146・決147 の 4)

## 1. 背景(Context)

- dcr が社名の表の第 1 版(社 9)を作り、当たる正本の 7 本(作業標準 2・規程と基準 4・前の説明書 1)の書き出しを、伏せた版に書き換えた(rep 20261118-0120・check_input 7/7・前の版は各本の `kgb_input_prev_20261118-0119/`)。決142 の止めを解くには、この 7 本を正本で入れ替える要がある(決96)。
- 読んで分かったこと(確定・コードと正本の読み取りで確かめた):
  1. **入れ替えが K0 で止まる**: dcr の伏せは、`_meta` の版を見分ける欄(作った時刻・道具のコミットなど)を変えない。投入の道具は、Document の属性が同じなら「同じ版」とみなし、入れ替えを止める(`scripts/kg/ingest.py` の `same_doc_version` と K0)。
  2. **API の守りが変わりを拾わない**: API の「入力の変わり」の守り(`changed_inputs`)も同じ照らしなので、7 本を 0 本しか拾わない(正本で数えた)。決133 §3 の限り(指紋が無い)が、そのまま出た形である。
  3. **K2 で説明書が止まる**: PDF を根拠にする説明書(866024c69f4e2458)は、伏せた字を、伏せていない読取の行の字と照らすので、逐語で合わない(dcr の頼み)。Word と Excel の 6 本は、読みの流れも伏せてあるので合う。
- 利用者の選び(2026-11-18・この画面): 7 本を今の伏せた版で、1 つの dec で入れ替える。説明書の誤読の直し(dcr がこれから諮る)は、後で別の dec でその 1 本を入れ替える。

## 2. 直し

### 2-1. 伏せた版を別の版として見分ける(`scripts/kg/ingest.py` の `doc_props_of`)

- `_meta` に `x_company_mask` がある本は、Document に `company_mask_table`(伏せに使った表の版の番号)の属性を足す。無い本は今のまま(属性を作らない)。
- これで、伏せた版は前の版と別の版になり、K0 を通る。API の守りも、入れ替えの前の 7 本を「入力が変わった本」とみなし、返せない本として返す(正しい向き)。
- Document の属性の足しは、スキーマの変更なので、本計画の承認で認めてもらう。グラフの中身が変わるのは、入れ替えた 7 本の Document だけ。

### 2-2. 投入の記録に入力の指紋(決132 §3・決133 §3)

- K1 で、入力のファイル(`_meta.json`・`elements.jsonl`・在れば `stream.jsonl`)の sha256 を、投入の記録の `input.files` に書く。
- API の `changed_inputs` に足す: 最新の投入の記録が `input.files` を持てば、今のファイルの指紋と照らし、違えば「入力の変わり」とする。持たない記録(今までの 126 本)は、今の照らしのまま(後ろ向きに合う)。
- これで、`_meta` を変えずに要素のファイルだけを書き換えた形も、入れ替えた本から先は拾える。API の版は 1.0.3(型は変わらず、答えが変わりうる直し・凍結の 1 枚 第 7 版に対応を足す)。

### 2-3. K2 の照らしに伏せを掛ける(dcr の頼み)

- `_meta` に `x_company_mask` がある本は、PDF の行の流れの字(と、事例報告の単位の字)に、dcr の `company_mask_core.mask` を同じ表で掛けてから、逐語で照らす。
- 表は、`derived_from` の `company_table` の記録が指す物を読み、指紋が記録と合うことを確かめる(合わなければ K2 で止める)。表の版のファイル(`table_v<版>.json`)が在ればそれを使う。表の字は記録にも画面にも出さない(数だけ)。
- 投入の道具が表を読むのは、照らしの道具として(決146 §4 の 1 の「照らしの道具」)。

### 2-4. 入れ替えの照らし R1〜R6(新 `scripts/kg/masked_replace_check.py`)

- 前の版(投入の記録の前の計画)と新しい版の計画を、本ごとに照らす。数と真偽だけを出す。
  - R1: 節点の id とラベル・辺の組が同じ。
  - R2: 変わった属性は字の属性と `company_mask_table` だけで、字の属性は全部「前の字に伏せの関数を掛けた字」と一致する。
  - R3: 新しい版の字に、表の字が 0。
  - R4: ほかの本の本ごとのダイジェストが同じ(演習の DB で)。
  - R5: 本の外の節点への辺が 0。
  - R6: 演習の DB で API を立て、確かめ済み 126 本・入力の変わり 0・返せない本 0。

## 3. 順

1. 2-1〜2-4 を作る。投入の道具と API の selftest に場面を足す(合成の資料と合成の表だけ)。
2. LOCKS に 9391 を予約し、7 本の入れ替えの演習(`ingest.py run --mode rehearse --replace`)を回す。K0〜K8 と R1〜R6 の結果を、本ごとの合否・ほかの本の不変・前の版との照らしの数で rep に書き、coord に 7 本を名指しした 1 つの dec を頼む。
3. dec の後に本番(`--mode commit --replace --dec`)。終わりのダイジェストと照らしの数を rep に書く。dcr が `verify --canonical` を回す(決142 の解く条件 (c))。
4. 説明書の誤読の直しは、dcr の計画と書き出しの後に、その 1 本の入れ替えとして別の dec で行う。

## 4. 確かめ

- `ingest.py selftest`: 伏せた版が別の版として K0 を通る・伏せていない同じ版は今のとおり止まる・K2 の伏せの照らし(合う・表の指紋が違えば止まる)・`input.files` を書く。
- `kb_api.py selftest`: 指紋の違いで入力の変わり・指紋の無い記録は今のとおり・版 1.0.3。
- `masked_replace_check.py selftest`: 合成の前と後の計画で R1〜R3 が合い、外れも拾う。
- 演習と本番の数(上の 3)。実の表を使う照らしは、数だけを出し、表の字を出さない。
- 監査と検査: `audit_qa.py run`、漏れの検査(worktree と diff の行の数 = 三点の numstat・コミットの文)、QA の写しの照らし。merge は単独で回す。
