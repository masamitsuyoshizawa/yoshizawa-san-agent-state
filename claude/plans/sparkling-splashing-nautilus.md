# 計画: 図面の入力の契約 v0.8(機器と部分・注記の項・種類の根拠・名称表の結び)

## 1. 背景(Context)

- 利用者の備考(dgr の rep 20261122-2232 §3 の a): 同じ機器の巻線の記号と接点の記号が、図の中で離れて描かれる。この関係を持たないと、図を分かった事にならない。巻線に電気が通ると接点が動く、という働きの関係まで言っている(coord の添え)。
- 決201(dgr の画面・2026-11-23): 部分の語は 巻線・接点・本体・その他 の 4 語。「不明」は置かず、決まらない物は部分を空のまま未確認。問い K で採った単位 1 つを機器 1 つにする。採らない単位(未確認・組の誤り)と、配線の付記(電線の種類)の記号は機器にしない。語は kgb の画面でも承認が要る(統制語彙の変え)。dgr は両方の承認の後にプロファイルへ足す。
- 決197・決200: 1 つの注記(番号つきの 1 項)が 3 つの要素に割れて読まれていた。注記を項にまとめ、番号と本文を分け、元の要素を指す。種類の根拠は、複数の要素か、まとめた 1 項を指す。
- 決186・決191: 記号の種類「切り離し点」(プロファイルに入った)。
- 今の型(確定・コードで確かめた): 正本の図面 3 枚は旧方式の契約 v0.4。記号は種類の字(自由)と、共有の `Device` への `OF_DEVICE`(語彙の登録まで待ち)だけで、機器の束ね・部分・注記の項の型は無い。API 1.0.3 に図面の口は無い。新方式の書き出しは、まだ無い。
- dgr との合わせ(info 20261122-2237・dgr の rep 20261123-0131 §3): 束ねの単位・欄の名(dgr の書き出しの道具で契約の名へ写す)・電線の種類の扱いは、dgr の案に合わせた。
- 本計画は、絶対規則 4 のスキーマと統制語彙の変更の承認を兼ねる。11-05 の案(C1〜C11)のうち、本版に入れるのは C6(種類と根拠)と C11(注記の番号)を改めた形だけ。

## 2. 部分の語(統制語彙)

| 語 | 鍵 | 付き方(決201・dgr のプロファイル) |
|---|---|---|
| 巻線 | `winding` | 巻線の記号の種類から決まりで |
| 接点 | `contact` | 接点の記号の種類から決まりで(a 接点と b 接点の別は記号の種類が持つ) |
| 本体 | `body` | そのほかの種類から決まりで |
| その他 | `other` | 利用者の答えでだけ |

- null = 未確認(語にしない)。
- 利用者の選び(2026-11-23・この画面): 語 4 つと鍵の字を承認する。一覧は契約の型の決まった値(enum)で持つ(語彙の台帳にしない・端子の種別と同じ扱い)。

## 3. 契約 v0.8(図面だけ・1 つの型で前の版も受ける)

### 3-1. 機器(新しい要素の型 `DrawingDevice`)

- `attrs.code_raw`: 機器記号の字(番号の無い組は名の字)。
- `attrs.name_row = {status, table, row, table_version, basis, answer_ref}`。status は `row`(表の行を採った)か `not_in_table`(名称表に無い)。row の時は table・row・table_version が要る。basis は `human` か `rule`。
- 出典: 束ねた記号の eid の並び(枠は記号の側に在る)と頁。
- 採った単位だけを機器にする(決201)。

### 3-2. 記号 → 機器(新しい辺 `PART_OF_DEVICE`)

- 記号の links に `{"rel": "PART_OF_DEVICE", "to_eid": <機器>, "props": {"part": <鍵か null>, "part_basis": {"source": "kind_rule" | "human", "refs": [...]}}}`(今の型の links は props を持てる)。
- 記号 1 つは機器 1 つにだけ属する。part が null(未確認)の時は part_basis を持たない。

### 3-3. 注記の項(`Note` = 1 項)

- `attrs`: `struck`(今のまま)・`number`(整数か null)・`marker_raw`(印の字)・`members`(読取の元の要素の id の並び)。`raw` は本文(印を除く)。
- 出典: 元の要素ごとの枠の並び(新しい出典の形 `prov_drawing_multi`)。

### 3-4. 記号の種類と根拠(C6 を改めた形)

- `attrs.kind`: プロファイルの `symbol_kinds` の語(「切り離し点」を含む)か、その他・不明。
- `attrs.kind_basis = {source, refs}`。source と refs の先:

| source | refs |
|---|---|
| `name_table` | 名称表と行と版(決159〜決161・決165 の当てはめの出所) |
| `note`・`legend` | 同じ図の `Note` の eid(1 つ以上・項ができる前は割れた要素をいくつか・取り消された注記は指さない) |
| `standard` | 規格の節と目録の版 |
| `doc` | `<sha16>:p<頁>` |
| `human` | 答えの記録の id(「注記で定めていない」の答えもここ) |

### 3-5. eid

- 機器と注記の項の eid の書式は dgr と合わせ、I10 の表に足す(警告だけ)。

## 4. 入力の検査(`scripts/kg/check_input.py`)

| 規則 | 中身 |
|---|---|
| I22 | 記号の種類が `_meta` のプロファイルの版の `symbol_kinds` の内か、その他・不明。kind_basis の source の語と refs の先の型。取り消された注記を指さない |
| I23 | `PART_OF_DEVICE` は記号 → 同じ図の機器。1 記号 1 本。part の語。null なら根拠を持たない。機器は記号を 1 つ以上持つ。name_row の status と必須の欄 |
| I24 | 注記の項の members が 1 つ以上で、項の間で重ならない。number と marker_raw は両方在るか両方無い |

- v0.8 より前の図面は、これらの欄を持たない(I19 と同じ形)。`TO_EID_RELS` に `PART_OF_DEVICE: ({Symbol}, {DrawingDevice})` を足す。

## 5. グラフ(`scripts/kg/ingest.py`)

- 節点 `DrawingDevice`(`ddev:<sha16>:<局所>`・`PREFIX` に足す)。`a_code_raw` と name_row の平らな属性。
- 辺 `PART_OF_DEVICE`(`p_part`・`p_part_basis_json`)。`Note` に `a_number`・`a_marker_raw`・`a_members_json`。`Symbol` に `a_kind_basis_json`。
- 巻線と接点の働きの関係は、辺を足さず、同じ機器の束ねの中で、部分が巻線の記号と接点の記号を決まりで引く(利用者の選び・2026-11-23)。図をまたぐ時は、名称表の行が同じ機器で引く。設計書に Cypher の例を書く。
- 共有の `Device` への `OF_DEVICE` は今のまま(機器の節点から張る形は、語彙の登録の時に諮る)。

## 6. API

- 1.0.3 のまま変えない(利用者の選び・2026-11-23)。図面の口(機器の部分ごとの記号・巻線 → 接点と逆)は、新方式の図面を正本に入れる前に、API の版の案として別に諮る。設計書には口の形の枠だけ書く。
