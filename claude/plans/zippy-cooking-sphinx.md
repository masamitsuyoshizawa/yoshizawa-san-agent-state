## 3. 作るもの・直すもの・使い回すもの

- P1(直す): `proto/real01/img/scope.py`
  - 今は `DASH` の既定値と `rules.get(...)` が道具の中に散っている。`tables`・`uncross`・`inline_symbols`・`through_symbols`・`box_edges`・`tidy` の入り切りを、1 つの表(`rules_scope.json`・管理外・図の種類ごと)から読む。
  - 表に無い決まりは今の既定のまま動かし、今の出力と同じになることを確かめる。
  - `proto/real01/img/test_img.py` に、決まりごとの合成の図の試験を足す(交わり・曲がる点・T 字・箱の辺・表・線の上の記号・黒丸の端子)。
  - 利用者の答え「黒丸の無い T 字はつながっている」は、表の 1 行(`tee_without_dot: connected`)として残す。
- P2(使い回す): `checker/circuit_round.py`(`conn_share` で図ごとの数を決める)・`checker/panel.py`・`checker/demo_walk.py measure`。画面は変えないので、iag の点検は要らない(基本ルール C27)。
- P3(直す): 予備情報の文書(管理外)。リポジトリには、問いの型だけを記録に書く。
- P4(使い回す): `img/scope.py` の `inline_symbols`・`through_symbols` の考え方を、`proto/real01/vec/` の回路の組み立てに当てる。座標の単位が違うので、値は表で分ける。
- P5〜P7(使い回す): `vec/geom.py`・`checker/group_round.py`・`checker/sample.py`・`checker/score.py`・`tools/validate.py`。

## 4. 入れないもの(理由つき)

| 宿題 | 入れない理由 |
|---|---|
| 記号の見落としの読み直し(違う線番がつながる所のまわり・推定 20〜30 か所) | VLM の読取が約 123 万トークンで、止める条件(150 万)を超える見込み。「枝ごとに線番が違う書き方があるか」の答え(P3)で、読み直す所の数が変わる。答えの後に、別に諮る |

| 目録の、名の段が括弧で始まる 34 項(同じ分かれ方の疑い) | 統制語彙の変更に当たる。一覧を作って、別に諮る |

## 5. 顧客・有識者への問い(P3 に書く物)

1. 1 つのつながりに、枝ごとに違う線番(末尾の字が違う物)を付ける書き方があるか。
2. 太い線の上の黒丸に名が付く所は、機器の端子と読んでよいか。
3. 名が答えられなかった 3 つの形の記号の名。
4. 束線の中で、同じ線番の配線は必ず 1 本につながるか(今はそう読んでいる)。

## 6. 止める条件

1. P1 で、表から読むようにした後の出力が、今の出力と変わったとき(原因を調べて伺う)。
2. P2 で、主回路の正しさが代表 10 本中 5 本を下回るとき(直しを足さず、型を数えて記録し、伺う)。
3. P4〜P7 で、coord の時間かトークンが §1 の 3 の目安の 2 倍を超えるとき。
4. 新しい図の約束が見つかったとき(決まりを足す前に、表の 1 行として諮る)。

## 7. 検証

1. P1: 表を入れる前後で、2 文書の出力の sha256 が同じであること(実行の時刻を固定)。`test_img.py` が全て通ること。決まりを 1 つ切ると、その決まりの試験だけが落ちること。
2. 型と参照: `tools/validate.py` が NG 0 であること。
3. 照らし: 「1 つのつながりに入る線番の数の最大」「線番が 1 つだけのつながりの数」「配線だけの輪の数」を、毎回の報告に出すこと。
4. P2・P7: `checker/score.py` で層ごとの数と区間を出すこと。配る前に、実の回で見え方を数えること(`demo_walk.py measure`)。
5. 漏洩の点検: コミットするファイルで、禁止語の件数・作業の名と置き場の型・識別子の型・規格の文の断片が全て 0 件であること。`find proto -name __pycache__` が 0 件であること。
