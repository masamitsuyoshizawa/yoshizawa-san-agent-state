# 名称表 9 頁を、3 種の LLM で書き写し、決定論で照らす(決161 の段 4 の読み方を改める)

## 1. 背景(Context)

- 決161 の段 4(表の取り出し)は「字の層を決定論で読み、人が確かめる(AI は使わない)」で承認された。段 3 までで、扱う頁は 2 冊で 9 頁、全部が H0 に合格している。
- 段 4 に入って測った事(決定論・数だけ):
  - 字の層は崩れている。記号と名称の表 5 頁(約 950 行)では、記号の欄で、記号の形(英数字と括弧)に合う読みは字の層が約 69%、手元の OCR(tesseract)が約 96% だった。2 つの読みの一致は約 36% で、どちらが正しいかは未計測。名称の欄は、2 つの読みがほとんど一致しない。
  - 9 頁は 2 種類に分かれる。記号と名称の表が 5 頁(80 頁の冊の 78・79、94 頁の冊の 73・74・75)。図面の目次(図面の名と図番の表)が 4 頁(80 頁の冊の 3・4、94 頁の冊の 2・3)。
  - どの頁にも、記号の絵の列は無い(確定・門を通る版を dgr の画面で見た・info 1326 の範囲)。決159 の計画の rep の「名称表には記号の絵の列がある見込み(推定)」は外れていた。字の層の外の墨の塊は、字の層が拾えなかった字だった。
- 利用者の選び(2026-11-19・dgr の画面の問い): 読み方は「LLM 3 種で読み、照らす」。決161 の「AI に読ませない」を改める。まず 1 頁で一致の割合を測って報告してから、残りに進む。

## 3. 作り方(新しい道具 `scripts/drawing/vol_read.py`)

送りの部品は、決52 の `scripts/drawing/cli_probe.py` をそのまま使う。`new_run`・`bwrap_args`・`command`・`execute`・`read_answer`・`version_in`・`drop_run`・`env_of` を使い、目印 A・B の照らしもそのまま行う。agy の呼び方と、決めた道具の外を使った回を採らない決まりは `scripts/drawing/p1_send.py` の `command`・`ALLOWED_TOOLS` に倣う。

1. `prepare`: 9 頁を `vol_mask.load_page`(H0 合格の門)で読み、送る絵を作る。
   - 記号と名称の表は、縦の罫線の 3 本組で表の塊を見つけ、塊ごとの縦の帯にする。
   - 長い帯は、字の層の行の位置で上下に分ける。行と行の間で切り、行を割らない。長い辺は 1600 画素までにする。
   - 目次の頁は、段の組(左右)ごとに切る。
   - 見込みは約 45 枚(推定)。目録(絵の sha256・頁・帯の矩形・字の層の行の数)を git 外の `data/derived/drawing_vol/<sha16>/read/inputs_v1.json` に書く。
2. `run --cli <c> [--items …] [--pilot]`: 送る前の門(合わなければ何も送らない)。
   - プロンプトと JSON の型の sha が、承認の記録 `scripts/drawing/prompts/APPROVED.json` の新しい段 `vol_tables_cli` と合う。
   - 絵の sha が目録と合い、頁のマスク版の sha256 が H0 で確かめた値と合う(load_page)。
   - 回数は、CLI ごとに「枚数 × 1.15 + 3」まで(決52 D8 に倣う)。合成の絵は CLI ごとに 10 回まで。
   - 記録は git 外の `runs/<cli>/<item>_r<k>/`(_meta: モデル・思考の強さ・CLI の版・プロンプトと型と入力の sha・秒・トークン)。
3. 並びの数の照らし: 返った行の数を、字の層の行の数と比べる。差が 1 割を超えれば送り直す(決57 に倣う)。
4. `merge`(決定論): 3 種の行を並べて合わせる。
   - 行の数が揃えば番号で、揃わなければ記号の欄の並びの合わせで合わせる。
   - 升ごとの一致(3/3・2/3・1/3)を、NFKC にして空白を除いた字で数える。
   - 記号の欄の照らし: 記号の形・区切りの字の行と頭の字の合い・区切りの中の並び順・重なり。
   - 字の層と手元の OCR の読みとの一致は、補助の数として出す(決めには使わない)。
   - 出力は git 外の `read/v1/tables.json`(升ごとの値・一致・候補・頁と帯と行の位置・出どころ)。
5. `status`・`selftest`: 合成の表の絵で、帯の切り方・行を割らない切り・並びの合わせ・一致の数え・照らしを試す。

### 承認を頼むプロンプトと JSON の型(新しく作る)

`scripts/drawing/prompts/vol_table_transcribe_v1.md`:

```
あなたは画像の表の文字を書き写す係です。判断・要約・言い換えはしません。

- 画像は、電気の接続図の冊子の中の表(機器の記号と名称の表、または図面の目次)の一部を切り出したものです。灰色に塗られた部分は意図的に隠してあります。隠れた部分は推測しないでください。
- 表の 1 行を 1 要素とし、上の行から下の行へ並べてください。各行は、左の列から右の列へ、セルの文字を配列で書き写します。空のセルは "" にします。
- 見出しの行も 1 行として含めます。どのセルにも字の無い行は書きません。
- 1 字だけが書かれた区切りの行も、1 行として書き写します。
- 目次の点線は写さず、点線の左の字と右の字を別のセルにします。
- 書かれている文字を、見えるとおりに書き写してください。英字の大文字と小文字は、見えるとおりに区別します。漢字・片仮名・英数字・記号も、そのまま写します。
- 読めない字は、1 字ごとに「〓」にします。推測で補わないでください。
- 返すのは JSON だけです。説明文や前置きは付けません。`n_rows` には `rows` の要素の数を入れます。

{"rows": [["……", "……"]], "n_rows": 1}
```

`schemas/vol_table_transcribe_v1.json`: `{"type":"object","properties":{"rows":{"type":"array","items":{"type":"array","items":{"type":"string"}}},"n_rows":{"type":"integer"}},"required":["rows","n_rows"],"additionalProperties":false}`(3 種で共通。CLI ごとの版が要れば `_<cli>.json` を足す・`cli_probe.schema_rel` の決まり)。

## 4. 順と止め

1. 道具と合成の試し(selftest)。合成の表の絵 1 枚を、3 種に 1 回ずつ送り、口と型と読み取りを確かめる。
2. rep を coord に出し、決161 の改めの dec を頼む(needs_user_approval: yes)。dec と取り込みの後に、実の頁を送る。
3. 試しの 1 頁(80 頁の冊の 78・記号と名称の表・帯は約 8 枚 × 3 種): 一致の割合・照らしに落ちた数・並びの数の差・秒とトークンを、rep で知らせる。
   - 記号の欄の 3/3 が 8 割以上で、3 種とも並びの数の照らしを通れば、残りの 8 頁に進む。
   - 下回れば止め、dgr の画面で利用者に諮る(帯の切り方や大きさの直しは、合成の図で試してから)。
4. 残りの 8 頁 → merge → 数を rep で知らせる → 段 5 の画面を作る(docs/08・agy の点検・配る前の rep)。
5. 検討の記録(docs/03 の様式・`docs/検討記録/`): 崩れた字の層・手元の OCR・3 種の LLM の比べ(数と母数)、行を割らない切り方、記号の欄の照らし。顧客の字は書かない。

- 手間(推定): 道具と試し 半日・試しの 1 頁 1 時間・残り 2〜3 時間(CLI の時間)・merge と照らし 半日。利用者の時間は、段 5 で 15〜30 分(推定・揃わない升の数で変わる)。
