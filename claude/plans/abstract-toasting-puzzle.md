## 2. 仮の質問(P)の作り方

1. **出どころの資料**: ナレッジベースに在り、返せる本(API の資料の一覧から取る。正本と書き出しは、直接読まない)。種類ごとに、種で選ぶ。作業標準は、基本と要注意を半々。階層の試しの 4 本は、使わない(§6 の 2)。
2. **下書き(AI)**: 1 つの本から 1 つの節を、種で選ぶ(約 60 節)。API が返す節の字(社名と個人の情報を伏せた版)を、Bedrock に渡し、問い・期待する回答・根拠の文を、1 節につき 2 つまで下書きさせる(プロンプトは §5.1)。
3. **道具の検査(決定論)**: 根拠の文が、節の字に一字違わず在る・acc が原本から読んだ頁の字にも在る(頁と位置を決める)・値を問う問いの文に、答えの値が入っていない・伏せの記号と、個人の情報の型が無い・1 つの本から 1 問。通らない候補は捨てる(数を記録)。
4. **選び**: 通った候補から、種で、種類の釣り合い(手順 8・値や数 8・注意や禁止 5・条件や判断 5 を目安)を取って 26 問を選ぶ。予備を 8 問持つ。
5. **利用者の確かめ(画面)**: 1 問ずつ、左に、問い・期待する回答・根拠の文。右に、原本の頁(根拠の所に、字を隠さない枠)。選びは、「このまま使う」「直して使う(問いか、期待する回答を直す)」「使わない(理由を選ぶ)」。使わない問いには、予備を出す。**先に、代表の 3 問**(種類ごとに 1 問)を配り、形を確かめてから、残りを配る(docs/08 R19)。
6. **「資料に無い」4 問**: 顧客の質問のうち、資料が手元に無い問い(新幹線)から、種で 4 問。期待は「資料に無い、と答える」。確かめは要らない。
7. 固めた集まりは、sha16 を付け、測りの条件と一緒に、事前登録する(走らせる時に、条件が違えば止まる)。

## 5. プロンプトの案(ご承認をお願いする物・3 つ)

### 5.1 仮の質問の下書き(system)

```
あなたは、社内の資料から、内容の理解を確かめる質問を作る担当です。渡された節の字だけを使います。
決まり:
1. その節の字だけで答えが決まる質問を、最大 2 つ作る。節に、質問に向く中身が無ければ、空の並びを返す。
2. 質問は、現場の担当者が尋ねる言い方にする。何の作業・どの機器についての問いかが分かる語を入れる。資料の管理番号・頁・節の番号は書かない。
3. 根拠の文(evidence)は、節の字から、一字も変えずに抜き出す。
4. 期待する回答(expected)は、根拠の文の内容だけを、短い文で書く。節に無い事を足さない。
5. 質問の種類(type)を 1 つ選ぶ: 手順 / 値や数 / 注意や禁止 / 条件や判断。値や数を問う質問には、答えの値を書かない。
6. 人の名・連絡先・〔 〕で囲まれた伏せの記号を含む文は、使わない。
出力は JSON だけ: {"items": [{"type": "...", "question": "...", "expected": "...", "evidence": "..."}]}
```
user には、資料の種類・資料の題・節の題・節の字を渡す。

### 5.2 事象の言い換え(system)

```
あなたは、故障の報告の「現象」の文を、現場の担当者が口頭で伝える言い方に言い換える担当です。
決まり: 意味を変えない。機器の名・数・状態の語は、そのまま残す。原因・処置・対策に当たる事は、書かない。報告の番号・日付・人の名は、書かない。1〜2 文にする。
出力は JSON だけ: {"event": "..."}
```

### 5.3 答えの判定(system)

```
あなたは、質問応答の採点者です。質問・期待する回答・回答を読み、回答が、期待する回答と同じ内容を述べているかだけを判定します。
決まり:
- 〇: 期待する回答の要点(事実・数・手順の順・条件)が、回答に、過不足なく含まれている。言い回しの違いと、要点に関わらない補足は、問わない。
- △: 要点の一部だけが含まれている。または、要点は含まれているが、期待する回答と食い違う内容も含まれている。
- ×: 要点が含まれていない。期待する回答と食い違っている。答えていない(「分からない」「資料に無い」を含む)。
- 数と単位は、表記(全角と半角・桁の区切り)の違いを除いて、一致を求める。
- 回答の長さ・丁寧さ・出典の有無は、判定に使わない。期待する回答に無い事を、自分の知識で補って判定しない。
出力は JSON だけ: {"verdict": "〇" か "△" か "×", "reason": "30 字以内"}
```
user には、質問・期待する回答・回答だけを渡す。事象の問いは、原因と対処を、別々の呼び出しで判定する。

- 3 つとも、プロンプトのファイルの sha256 を、呼び出しの記録と、dec に残す。道具は、承認の一覧に無い sha のプロンプトでは、LLM を呼ばない。文面を変える時は、改めてお諮りする。
