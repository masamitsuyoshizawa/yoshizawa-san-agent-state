# 計画: 前の説明書の誤読 1 語を、人の直しの欄(fixed)で直す(dcr・2026-11-18)

## 1. Context

- 社名の候補の確かめ(8732)で、利用者は「分からない」とした 1 語を、前の説明書(866024c69f4e2458)の PDF の 101 頁で見た。その結果、誤読と確かめた(2026-11-18・dcr の画面)。
  - その語は、スキャンの時に付いた OCR の層の読み誤りだった。正しい読みは「ステンレス製」(利用者の言葉)。
  - 社名ではないので、社名の表(第 1 版)では「社名でない」に入っている。
- 書き出し(kgb_input)では、その語は Chunk 1 つの raw と norm に 1 か所ずつある。
- 原文(raw)は変えない(絶対規則 2)。人の直しは、要素の fixed の欄に持つ。
  - 契約にこの欄がある(fix_method の値 manual)。作業標準の直しの 158 要素で使っている形と同じにする。
  - その形では、norm は raw から作ったまま。API は fixed があればそれを出す。
- 試し(書き残していない): 仮の字の fixed を、前の説明書の写し(契約 v0.3)に置いた。check_input は合格した。
- 前の説明書は、社名を伏せた 7 本の 1 つである。kgb の入れ替え(決96)は、直しと伏せを 1 回にまとめられる。

## 2. 作り(新しい道具 `scripts/dcr/reading_fix.py`・決定論・LLM なし)

1. **`add`(直しの台帳に足す)**
   - 回の答えから誤読の語を道具の中で取り出し、git 外の台帳 `data/private/reading_fixes/866024c69f4e2458.json`(600)に書く。端末と連絡文には語を出さない。
     - 答えの場所は、回 company_20261118-0005 の問い k8 の 4 行目(候補の語から「製」を除いた字)。
   - 台帳の 1 件 = 誤りの字・正しい字(ステンレス)・根拠(利用者が PDF の 101 頁を見た・日時)・確かめた人。
2. **`apply <sha16>`(書き出しに直しを入れる)**
   - 今の kgb_input を `kgb_input_prev_<時>` へ写してから書く。
   - raw に誤りの字を含む要素に、fixed(raw の誤りの字を正しい字に置き換えた字)と fix_method = manual を置く。
   - raw・norm・prov・eid は変えない。
   - 当たる要素の数が台帳の見込みと違えば、書かずに止める。
   - 書いた後に、社名の伏せ(company_mask_core.mask)を fixed にもかけ直す(2 度かけても同じ)。
   - `_meta` には次を記す。
     - 出どころ: role reading_fix・台帳の sha16
     - 直しの記録: x_reading_fixes(件数・要素の数・道具の版・日時)
   - 最後に check_input を通す。
3. **`check`**: 台帳の直しが、今の書き出しに入っているかを数える。
   - 読み直しで書き出しを作り直した時に、直しが抜けたら分かるようにする。社名の伏せの verify と並べて回す。
4. **`selftest`**: 合成のデータだけで確かめる。
   - fixed を置く・raw と norm は変わらない・当たる数の食い違いで止める・2 度かけても同じ・社名の記号を壊さない。

## 3. あわせて数えること(数だけ・直しはしない)

- 前の説明書の OCR の層の片仮名の語のうち、次の 2 つに当たる語の数を数える。
  - ほかの本に出ない語。
  - ほかの本に 3 か所以上出る語と 1〜2 字違い。
- 同じ形の誤読がほかにも残っていないかの見込みである。多ければ、確かめの回を別の計画で諮る。

## 4. 渡しと知らせ

- 道具をコミットしてから apply をかける。その後、rep で coord・kgb・acc に知らせる。
  - rep の頭に、dec の外の足し(本件・利用者の確かめの日時)を書く。
- kgb: 7 本の入れ替えに、前の説明書の直しも乗る。
- acc: 1 要素は、fixed が raw と違う。
- 読み直しで前の説明書の書き出しを作り直す時は、次の順にかけ直す(道具の説明に書く)。
  1. reading_fix apply
  2. company_mask apply

## 5. 検証

- `reading_fix.py selftest`(合成だけ)。
- apply の後:
  - check_input が合格する。
  - 前の版と比べて、変わった要素が 1 つだけで、足した欄が fixed と fix_method だけである。
  - `company_mask.py verify` で、表の字の残りと確かめていない形が 0 である。
  - `reading_fix.py check` で、入っていない直しが 0 である。
- コミットの前に、漏れの検査をファイルとコミットの文の両方にかける。

## 6. 手間(推定)

- 作りと試しは約 1 時間。利用者の手間は無し(確かめは済んでいる)。
